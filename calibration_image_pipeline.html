Stereo Camera Calibration — Image Pipeline

ROS 2 Jazzy + Gazebo (gz‑sim)  ·  Gazebo sim → ros_gz_bridge → calibration consumer.
Calibration consumes the unprocessed frames directly from the bridge (no intermediate republish node).
Source: diff_drive.launch.py (sim branch) + stereo_camera_package.

Stage 5 — board actuator (feeds back into Gazebo, not the image stream): chessboard_mover (and grid/cycler variants) is a gz‑transport client (not a ROS node). It discovers /world/demo/set_pose and issues gz.msgs.Pose requests to teleport calibration_board through many poses (80 poses, ~4 s each) so the cameras see the board from diverse depth / lateral / height / tilt viewpoints — which is what constrains the baseline and relative rotation.
Why no processing node: the former intermediate sim_stereo_camera_node (republished /image_raw + rebuilt CameraInfo) is no longer launched in the sim branch. The calibration consumers only need the raw pixel data — they do their own corner detection and calibration and do not consume the rebuilt CameraInfo. The node source remains in stereo_camera_package should other consumers (RTAB‑Map / image_proc) later need that stream.

The calibration input is the bridge's rgb8 output, unchanged. The calibration consumers convert with cv_bridge to bgr8 for corner detection; the headless node re‑publishes annotated views as bgr8. QoS: bridge publishes default (reliable); consumers use message_filters.ApproximateTimeSynchronizer. The previously‑published processed topics /stereo/stereo_camera/{left,right}/image_raw + camera_info are not produced in the sim launch anymore.

Post‑calibration verification (optional)

evidence_stereo.py / evidence_live.py / evidence_offline.py — load calibration_sim/{left,right}_sim.yaml, undistort+rectify, run SGBM disparity, measure epipolar row alignment, triangulate the board (recovered square vs true 0.04 m), and write calibration_sim/evidence/*.json + PNGs. (These standalone tools still point at the processed /image_raw topics; repoint them to /image_raw_raw to use the direct stream.)
regen_calib.py — re‑calibrate from the saved tarball and rebuild the stereo‑rectify P with fresh cv2.stereoRectify buffers (workaround for the OpenCV 4.6 in‑place P corruption), writing /tmp/calibrationdata_fixed.tar.gz.
